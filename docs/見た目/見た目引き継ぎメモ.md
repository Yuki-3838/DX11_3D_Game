# 見た目実装 引き継ぎメモ

最終更新: 2026-09-24  
対象ブランチ: `feature/hata-visual-polish`

## この資料の目的

このブランチでは、ゲームの見た目に関する実装だけを扱う。対象はライティング、マテリアル、テクスチャ、法線、影、カメラ、ポストエフェクト、パーティクル、モデルの表示調整などである。

既存の`docs/実装ログ.md`、`docs/Codex引き継ぎメモ.md`は、ゲーム全体の実装や他担当の引き継ぎと内容が混ざる可能性があるため、見た目実装の進捗・判断・検証はこの資料と`docs/見た目技術選定.md`へ記録する。見た目の変更を行った場合は、両方を更新する。

## 変更の境界

- ゲームルール、攻撃判定、敵AI、入力仕様は原則として変更しない。
- 見た目のために必要なデータ受け渡しや描画用バッファの変更は許可するが、戦闘ロジックの責務へ描画都合を持ち込まない。
- 既存のアニメーション、衝突、影の修正と競合しそうな場合は、まず対象ファイルの現在の差分と実行経路を確認する。
- 共通資料の既存記述を上書きせず、見た目側の判断はこの資料へ追記する。

## 現在の描画構成

- DirectX 11の前方描画。主な描画登録は`scene/GameScene.cpp`で行っている。
- 静的モデルは`CStaticMesh`、スキニングモデルは`CAnimationMesh`を使用する。
- 通常のモデルは`vertexLightingVS.hlsl` / `vertexLightingPS.hlsl`、スキニングモデルは`vertexLightingOneSkinVSHybrid.hlsl` / `vertexLightingSkinPS.hlsl`を使用する。
- マテリアルはAmbient、Diffuse、Specular、Emission、Shininess、Diffuseテクスチャに加えて、定数Metallic/RoughnessのPBR入力を持つ。Normal/AOとテクスチャ化したMetallic/Roughnessは未導入。
- ライトは方向ライト1つを基本とし、AmbientとDiffuseを定数バッファへ渡している。
- スキニングモデルの影は`shadowDepthSkinVS.hlsl`で深度を生成し、`common.hlsl`のPCF処理で参照する。壁・床の一部は意図的にUnlit描画を使用する。
- シェーダーは実行時コンパイルで、C++ビルド成功だけではHLSLの検証にならない。

## 見た目実装の優先候補

1. PBRの最小導入: まず方向ライト1つ、テクスチャなしの定数Metallic/Roughnessから検証する。
2. 法線マップ: 接線情報を頂点へ追加し、スキニング後のTBNを正しく作る。PBRと同時に入れる場合も、原因を分離できる小さな段階で確認する。
3. 環境光・IBL: PBRの反射を安定させるためのキューブマップまたは簡易環境近似。アセット準備とHDR/線形色管理が必要。
4. 影の質感: 現在のPCF影を維持しつつ、接触影、バイアス、解像度、ライト範囲を調整する。
5. ヒット演出・武器軌跡・画面効果: 既存の戦闘判定を変更せず、描画側の表現を強化する。

## PBRを始めるときの実装順

1. `MATERIAL`とC++側のマテリアルデータへ、定数Metallic/Roughnessを追加する。
2. 既存の方向ライト1つに対してCook-Torrance BRDFを実装する。最初はGGX NDF、Smith系の可視性、Schlick Fresnelを使う。
3. Diffuse色をsRGBから線形空間へ変換し、計算後にsRGB出力へ戻す。テクスチャの色空間を数値のまま混ぜない。
4. 既存のシャドウ係数を直接照明へ掛け、PBR導入前後で影の有無と明るさを比較する。
5. 必要になった段階でMetallic/Roughness/AO/Normalテクスチャへ拡張する。
6. 各段階でモデル、金属、粗い材質、鏡面に近い材質、影の境界を確認する。

## 検証ルール

- C++: `Debug|x64`をビルドし、終了コード0と`: error`がないことを確認する。
- HLSL: 実行時コンパイルと同じくStrictnessを意識し、変更したVS/PSは`fxc`で`/Ges`付き検証を行う。
- 描画: 起動直後の黒画面、テクスチャ未読込、法線反転、影の消失、白飛び、金属の過度な明るさを確認する。
- 比較: 見た目変更前後で同じカメラ、同じライト、同じモデルを使う。PBRと法線マップを同時に導入して原因を混ぜない。
- 実行画面を取得できない場合は、プロセス応答だけを「起動確認」とし、見た目の最終確認は未完了と記録する。

## 現時点の注意点

- PBRを導入しても、テクスチャがすべて正しい色空間で管理されているとは限らない。先に入力データの実態を確認する。
- 法線マップを追加する場合、現在の頂点形式にTangentがないため、頂点バッファ・Assimp読み込み・スキニングVSの全経路を揃える必要がある。
- 影の受け側を増やすと、`PS_IN`や各頂点シェーダーの出力初期化漏れで実行時コンパイルが止まりやすい。
- PBRの数式が正しくても、露出・環境光・トーンマッピングがないと暗すぎる、または白飛びする可能性がある。

## 2026-09-15 最小PBR＋露出調整

- 狙い: 既存の前方描画とPCF影を維持したまま、プレイヤー防具・敵・武器の材質差が出るライティングの土台を作る。
- 変更ファイル: `system/renderer.h`、`system/renderer.cpp`、`shader/common.hlsl`、`shader/vertexLightingVS.hlsl`、`shader/vertexLightingPS.hlsl`、`shader/vertexLightingOneSkinVSHybrid.hlsl`、`shader/vertexLightingSkinPS.hlsl`、互換用スキニングVS 2種、`shader/unlitTextureVS.hlsl`、`shader/GeometryShader.hlsl`。
- 実装内容:
  - `MATERIAL`の予備領域を`PBRParams.x=Metallic`、`PBRParams.y=Roughness`へ変更。
  - GGX法線分布、Smith可視性、Schlick Fresnelによる方向ライト1灯のCook-Torrance BRDFをピクセルシェーダーへ追加。
  - 既存のシャドウ係数を直接光へ適用し、スキニング後のワールド法線・ワールド位置を補間して計算。
  - `Shininess`から粗さを補うフォールバックを用意し、未設定の既存マテリアルを非金属・粗めとして安定表示。
  - `ViewParamsBuffer(b9)`へカメラ位置と露出を渡し、ACESではなく簡易Reinhard系の`1-exp(-color*exposure)`とsRGB近似変換を使用。
  - `Renderer::SetExposure()`を追加。初期値は1.15で、今後のデバッグUIやシーン別露出から変更できる。
- 見た目への効果: 光の方向による陰影がピクセル単位になり、ハイライトの幅が粗さに応じて変化する。影の中でも環境項が残り、暗い防具の輪郭が完全には潰れない。
- 採用理由: Deferred化やIBL用アセットを先に導入せず、既存の方向ライト・影・頂点形式を再利用して原因を分離できるため。
- 現時点の限界: Metallic/Roughnessテクスチャ、法線マップ、IBL、露出の実行時UI、HDRバックバッファは未導入。テクスチャはUNORMで読み込まれるため、PBR経路ではシェーダー内でsRGB相当の線形化を行っている。`MATERIAL.PBRParams`のレイアウトは追加したが、既存の`CMaterial`はレガシー項目を個別コピーする実装なので、現状の読み込みモデルは`Shininess`フォールバックが中心になっている。
- ビルド/HLSL/実機確認: 変更した8シェーダーを`fxc /Ges`で確認済み。`Debug|x64`ビルド成功、ビルドエラー0。実機画面での材質比較は次の確認で行う。
- 不具合と修正: 初回実装ではC++側の`MATERIAL`で`BOOL`直後に`Vector4`を置いたため、HLSLの16バイト境界配置とずれて定数バッファが88バイトになり、起動後に`d3d11.dll`アクセス違反が発生した。`float Dummy[2]`を明示的な境界調整として残し、`PBRParams`を次の16バイト境界へ置いてCPU/HLSLを96バイトに統一した。`static_assert`も追加済み。
- 次に確認すること: 起動後にプレイヤー防具、敵の鱗、剣、床の4対象を同じカメラで確認し、暗すぎる場合は露出と環境項を調整する。次段階は法線マップではなく、まず`CMaterial`までマテリアル別Metallic/Roughnessを伝搬する設定経路を整える。

## 2026-09-16 プレイヤー暗部・質感調整（全体調整としての試行）

- 狙い: PBR導入後に暗くなりすぎたプレイヤー防具を見やすくし、既存のSpecularとテクスチャの質感を反射へ戻す。
- 変更内容:
  - テクスチャ経路だけをsRGB相当から線形化し、頂点色・マテリアル色を二重にガンマ変換しないようにした。
  - 既存`Specular`を非金属のF0へ反映し、旧`Shininess`から求める既定Roughnessを少し滑らかにした。
  - 拡散反射だけへ軽いwrap照明を加え、逆光時も防具の面と模様を読めるようにした。鏡面反射は通常のNdotLを維持した。
  - 環境光を0.20から0.28、初期露出を1.00から1.15へ調整した。
- 見た目への効果: プレイヤーの黒い装甲の暗部が潰れにくくなり、テクスチャの色とスペキュラハイライトが見えやすくなる。
- 限界: 法線マップ、Roughness/Metallicテクスチャ、IBLはまだ未導入。wrap照明と環境光の強さは、床や敵が明るくなりすぎないか実画面で再確認する。
- 追加対応: `CStaticMeshRenderer`が保持する`MATERIAL`を描画直前に`Renderer::SetMaterial()`へ渡すようにし、PBRParamsが旧`CMaterial`の個別コピーで失われないようにした。これで静的装備・スキニングメッシュ内の装備・剣のマテリアル設定を同じPBR経路へ通せる。
- 検証: 変更後に再度HLSLの全経路とDebug x64ビルド、起動安定性を確認する。

## 2026-09-16 敵ドラゴンの白飛び抑制と鱗の質感調整（試行記録・現在は撤回）

- 狙い: 敵の白みがかったハイライトを抑え、元テクスチャの暗い赤茶色と鱗の凹凸を見せて、ドラゴンらしい重量感を出す。
- 原因: 敵の`dragon.png`は暗い赤茶系だが、PBRの鏡面反射が共通設定で計算されるため、光が当たった面の白いハイライトが強く見えていた。敵用の粗さ・色補正がなかった。
- 実装内容:
  - 敵モデルの同一UV配置の代替テクスチャ`dragon_black.png`を使用し、黒い鱗と赤みのある腹部を明確に出す。`dragon.dae`と`dragon.mtl`の参照を更新した。
  - 敵描画中の`CharacterVisualParams`を`(0.0, 0.28, 0.92, 0.0)`に設定。明るさは上げず、鏡面反射倍率を下げ、粗さを`0.92`へ上書きする。
  - 敵描画中の`CharacterAlbedoParams`を`(0.88, 0.68, 0.56, 1.0)`に設定。ベースカラーを赤茶へ寄せ、シェーダー側でも反射色を鱗の色へ寄せる。
  - 敵の描画後に両方の値を初期値へ戻し、プレイヤー・床・壁へ漏れないようにした。
- 見た目への効果: 黒い鱗のシルエット、赤みのある腹部、粗く控えめなハイライトが出る。光沢が広く白く広がってドラゴンの色が消える状態を避ける。
- 採用理由: テクスチャを加工・置換せず、既存のドラゴン素材を活かしたまま敵だけの材質感を調整できるため。
- 不採用案と欠点: 全体の露出を下げる方法はプレイヤーや背景も暗くなるため不採用。敵へ黒い色を一律加算する方法は鱗の色差を潰すため不採用。新しいテクスチャを生成する方法は元アセットとの整合性確認が必要なため後回し。
- 現時点の限界: 法線マップやAOマップはまだ敵へ接続していないため、鱗の立体感は頂点法線とDiffuseテクスチャに依存する。黒テクスチャと色補正を強くしすぎると暗部が潰れるため、実画面で最終値を確認する。
- ビルド/HLSL確認: `CharacterVisualParams`と`CharacterAlbedoParams`を含む8経路を`fxc /Ges`で再検証成功。C++の`Debug|x64`ビルドも成功し、実行ファイルを18秒起動して応答状態を確認済み。
- 次に確認すること: プレイヤーと敵を同じ照明で並べ、敵の白飛び、赤茶色、鱗のハイライト、影の濃さを確認する。必要なら敵の値だけを微調整する。

## 2026-09-24 材質バッファ経路の修正とキャラクター材質プロファイル（最新）

- 狙い: 色倍率だけの調整ではなく、プレイヤー防具と敵ドラゴンをMetallic/Roughnessの違いで見せる。白いプラスチックのような反射を抑え、テクスチャ本来の色と陰影を残す。
- 原因: `CStaticMeshRenderer::Draw()`で`CMaterial::SetGPU()`を呼んだ後、`Renderer::SetMaterial()`がCPU側の共有マテリアルバッファを更新するだけで、VS/PSのb3へ再バインドしていなかった。そのため、追加した`MATERIAL.PBRParams`がシェーダーへ届かず、古い材質値で描画されていた。
- 実装内容:
  - `Renderer::SetMaterial()`で更新後の共通マテリアルバッファをVS/PSのb3へ再バインドするようにした。
  - `CStaticMeshRenderer`で旧`Shininess`を`Roughness`へ変換し、値が無いモデルでも完全な鏡面にならない既定値を設定した。
  - `CStaticMeshRenderer::ApplyCharacterMaterialProfile()`を追加した。ドラゴンは非金属・粗さ`0.84`、プレイヤーはサブセット名の`armor/plate/helmet/shield/steel`等を金属、`cloth/leather/skin`等を非金属として分類する。1枚のテクスチャアトラスを共有する部位でも、サブセットごとに描画時のPBR値を分ける。
  - 旧Phongの`Specular`をそのままF0へ使わず、非金属のF0`0.04〜0.08`へ圧縮した。Metallicが高い鎧だけはBaseColor由来の反射へ寄せる。
  - ドラゴンは黒テクスチャへの置換を取りやめ、元の`dragon.png`の赤茶・黒・腹部の色差を使う。敵描画区間のアルベド一律色補正も解除し、粗さと低めの反射倍率だけを適用する。
- 見た目への効果: 鎧の金属部は色付きで締まったハイライト、布・革は広く弱い反射、ドラゴンは白く塗り潰れにくい粗い鱗として描画される。テクスチャを単色化しないため、元アセットの色差を維持する。
- 採用理由: 実際にシェーダーへ届いていなかった経路を先に直す必要があり、全体露出を変えずに材質差へ責務を戻せるため。黒テクスチャへの置換だけでは色差が減り、ドラゴンの質感改善を確認しにくいため元テクスチャへ戻した。
- 不採用案と欠点: シーン全体の露出・環境光を上げる方法は敵・床・壁まで変わるため不採用。ドラゴンを黒く一律着色する方法は鱗の色差を潰すため不採用。法線マップは現時点でTangents/TBNと対応テクスチャが揃っていないため、今回は接続していない。
- 保留: GLB/AssimpのPBR係数を直接取り込む案は、初期化中の早期終了を確認したため今回の実装から外した。まず安定しているサブセット別プロファイルを採用し、後で小さな検証経路として再調査する。
- 現時点の限界: Metal/Roughnessテクスチャ、Normal/AO、IBLは未導入。プレイヤーの部位分類はモデルのサブセット名に依存し、名称が無い部位は控えめな中間値になる。方向ライト1灯のため金属の環境反射は簡易的である。
- ビルド/HLSL/実機確認: 変更シェーダー8経路を`fxc /Ges`で検証成功。`Debug|x64`ビルド成功。実行ファイルを18秒起動し応答状態を確認済み。画面の最終的な質感比較はユーザー側の実画面確認が必要。
- 次に確認すること: プレイヤーの鎧・布・剣、敵の頭部・胴体・腹部を同じカメラで確認する。部位名分類が効いていない箇所があれば、追加の材質名ルールを入れ、法線マップはその後に進める。
